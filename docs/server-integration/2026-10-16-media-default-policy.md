# 媒体默认策略接入（2026-10-16）

## 变更范围

服务端增加鉴权的只读策略接口和 Overmind 配置；端侧为未配置的账户预选图片、视频模型。用户手选、关闭状态优先。现有模型列表数组、生成接口、计费、状态查询与退款协议保持兼容。

端侧目标分支为 release/2026.10.13。策略接口为增量能力，服务端和客户端可以独立发布。

## 接口

GET /api/media/default-policy

请求头：
- Authorization: Bearer <accessToken>
- X-Lobster-Media-Capabilities: media-default-policy-v1

账户与企业身份仅使用现有鉴权解析器的认证上下文，调用者不能通过参数切换账户。响应 Cache-Control: no-store。没有能力声明、未灰度、无权益、配置关闭或默认模型不在当前账户可见列表内时，不返回该默认项。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "schemaVersion": 1,
    "policyVersion": "media-defaults-canary-1",
    "ttlSeconds": 900,
    "eligible": true,
    "defaults": {
      "image": {
        "enabled": true,
        "modelId": "doubao-seedream-5-0-260128",
        "modelName": "Seedream 5.0 lite",
        "params": { "size": "2K", "n": 1 },
        "maxOutputsPerTurn": 1,
        "confirmation": null
      },
      "video": {
        "enabled": true,
        "modelId": "doubao-seedance-2-0-fast-260128",
        "modelName": "Seedance 2.0 fast",
        "params": { "resolution": "720p", "durationSeconds": 5 },
        "maxOutputsPerTurn": 1,
        "confirmation": "every_submission"
      }
    }
  }
}
```

模型名称来自当前可见模型 DTO，示例名称不是固定值。eligible=false 时 defaults 为空对象。接口不会扩大媒体权益：个人沿用现有 hasPaidCredits/媒体权益，企业另外检查媒体权益及可用额度。

## Overmind

配置键：media.defaults.v1。示例配置见服务端 docs/specs/media/media-defaults-canary.json。

- 配置缺失或删除：关闭自动默认；不会删除用户手选模型。
- 无效更新/读取异常：服务端保留最近一次有效配置；首次启动无有效配置时关闭。
- enabled=false 或 rolloutPercent=0：关闭自动默认。
- rolloutPercent 为 0—100 整数，按认证账户与企业作用域稳定分桶，增加比例不会随机洗牌。
- enterpriseEnabled 默认 false；企业独立启用，仍走原企业模型可见性和额度检查。
- 图片 params 支持 size、n；n 固定为 1。视频支持 resolution、durationSeconds（1—15）。
- ttlSeconds 为 60—3600。客户端以账户、登录代次、服务端地址隔离缓存，缓存过期后获取失败不继续执行旧默认。
- 视频确认要求不可通过配置关闭。接口能力声明只代表支持此协议，不构成用户扣费授权。

## 端侧合并与迁移

主进程 MediaDefaultPolicyManager 是偏好读取、迁移和默认合并的唯一入口。偏好使用 media_preferences.v1:<ownerAccountKey>，每种媒体为 inherit/off/selected，保存 revision。

1. 新旧账户键均不存在且读取成功：inherit。
2. 旧键已有两种模型：保持两种手选。
3. 旧键只有一种：保留该模型，缺少的另一种按 off 迁移。
4. 旧键为 {}：两种均 off。
5. 旧模型不可用：保留偏好，执行时提示重新选择；不能静默换用收费模型。
6. 读取异常或坏数据：不当成新用户，失败关闭自动能力。
7. 用户点已选模型或“关闭此类生成”：持久 off。“恢复系统默认”：重新 inherit。
8. 自动默认不会写入手选模型。主动修改偏好时维护旧键镜像，旧端不会把系统默认误认成手选。
9. 账户/企业切换、异步刷新及用户连续改选，以账户代次和偏好修订号防止旧结果覆盖。

无配置/旧服务返回 404 时，新端仍恢复原有手选模型。旧客户端不调用新接口，继续原行为。客户端版本号不是能力判断依据；正式发布版本由正常发布流程管理。

默认解析在回合提交时再次执行并固定快照；模型菜单只是展示和修改偏好。桌面专家继承同一策略，无需强制改写专家或个人设置。专家召唤自动带入的技能记录 inheritedSkillIds，避免将其误判为用户手动选择 seedream/seedance；用户移除后重新选择则恢复为手动来源。IM/cron 等网关原生回合沿用 release 分支的模型解析、账户隔离和引用规则，不继承桌面回合的自动默认快照。

## 执行边界

- Plan 回合禁止媒体生成；关闭状态经过 Redux、IPC 和父子会话传递，不跳过 off 回退到父会话。
- 用户直接选择 seedream/seedance 技能时，相应系统默认让位，另一类默认不受影响。
- 系统默认提示词说明“可用不等于授权”；数据图表、思维导图、界面源码、文章排版、脚本及既有素材剪辑优先相应确定性工具。
- 默认图片每次生成一张，根回合与子任务共享一次自动生成额度。额外调用/重试在提交前确认；已确认选择的手动模型沿用原行为。
- 可信皮肤 Kit 保留两资源预算；用户明确关闭优先。
- 视频每次生成都要由客户端明确确认，提示词要求模型直接调用原生工具呈现确认，不另行重复提问。取消、超时、空响应、缺少答案与非确认答案都不会提交；确认展示模型、规格、时长及生成描述。
- 已运行回合不会因为策略刷新中途换模；现有任务查询、文件取回、幂等恢复与退款不受默认开关影响。
- 复用媒体生命周期埋点，增加 selectionSource/policyVersion 和默认曝光事件。既有 task/turn/preset 上下文用于后续灰度分析。
- 单次视频费用仍按服务端实际参数和计费规则结算；本次没有新增报价接口，不将单位价格伪装成整单承诺价。

## 上线与验证

可以按“服务端上线 → 发布生产 Overmind 配置 → 配套客户端随新包发布”的顺序执行。旧客户端不调用新接口，也不会因配置已开启而改变行为。配置发布后，已安装支持 media-default-policy-v1 的客户端会开始按账户灰度取值；它不是按安装包发布时间或具体版本号限流。

1. 服务端上线：先在不配置 media.defaults.v1 的状态下验证鉴权、旧模型列表和生成接口，新接口应返回 eligible=false、defaults={}。本功能没有数据库迁移。
2. 生产配置预检：核对生产模型 ID、上架状态、可见范围、套餐权益、供应商路由和计费；测试环境可见不代表生产环境可见。图像 ID 为 doubao-seedream-5-0-260128（展示名 Seedream 5.0 lite），视频 ID 为 doubao-seedance-2-0-fast-260128。仅检查配置并不代表实际生成成功。
3. 发布独立的生产配置：建议个人账户 rolloutPercent=1、enterpriseEnabled=false；初期 ttlSeconds=60 便于观察和回滚，稳定后可提高到 900。每次调整记录新的 policyVersion 和操作时间。不要直接复用测试环境的 100% 灰度。
4. 使用候选安装包验收：完成正常安装和旧版升级，确认生产/测试环境选择正确、登录后默认模型出现、旧手选和关闭保持、视频取消不提交任务、专家和 Plan 行为正确。开发模式验收不能替代安装包验收。用受控账号验证两种真实生成，提前约定费用上限；如果账号未命中 1% 分桶，应先采用受控的包分发和配置组合，当前协议没有单账号白名单。
5. 随新包发布：保持 1% 账户灰度，先观察具备新协议且实际命中的用户；在至少一个业务高峰且有足够样本后，再按 5% → 20% → 100% 放量。此节比例和观察周期是操作建议，不是代码自动执行的规则。企业单独评估和启用。

“默认开启”只适用于具有媒体权益、模型可见、命中灰度且偏好为 inherit 的账户。旧版已保存的空对象 {}、缺失的一类选择按 off 保守迁移，升级后不强制开启；可通过“恢复系统默认”启用。专家继承同一账户偏好，不会绕过用户关闭状态。

监控按 policyVersion、selectionSource、媒体类型及客户端版本拆分。默认曝光事件为 MediaLifecycle/view、entry=default_policy；生成生命周期携带 selectionSource 和 policyVersion。用媒体服务端任务与账务核对实际提交数和积分，避免把已包含媒体费用的 API 调用合计与媒体任务费用重复相加。建议关注每千名默认曝光用户的媒体提交量、图片额外确认、视频确认/取消、成功率、失败/退款、额度消耗及用户关闭/误生成反馈。埋点只能表明发生了什么，不能仅据提交率判断任务是否误触发；需结合脱敏抽样和反馈。上线前确认埋点接收和统计查询确实可用，当前改动不包含现成的告警看板或固定异常阈值。

重点验证：旧配置迁移、关闭/恢复默认、登录/企业切换、旧服务回退、配置更新/下架、子任务预算、Plan、视频取消/超时/空响应、图片重复调用及皮肤两资源。

配置回滚优先将完整有效配置的 enabled 改为 false，或只关闭 defaults.image/video.enabled。空白/删除也关闭，但 {} 或非法 JSON 会保留上一次有效配置，不能用作回滚。先确认服务端接口已返回关闭，再验证客户端刷新后的新回合。客户端缓存和回合快照意味着回滚不是立即撤销授权；正在运行的回合以及在途媒体任务继续按原状态处理，用户手选模型也不受自动默认开关影响。若必须立即阻止故障模型的新提交，应使用已有模型停用/可见性机制，并单独核对在途任务、取消及退款处理，不将默认策略开关当成全局停机开关。
