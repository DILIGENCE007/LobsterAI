# 专家广场与配置下发设计文档

## 1. 概述

### 1.1 问题与背景

原有 Agent 模板藏在创建弹窗中，用户需要先理解 Agent 配置才能开始使用；“专家套件”的命名又容易与角色型专家混淆。模板、推荐场景及排序写在客户端，也使内容迭代依赖应用发版。

本功能将单专家建立在现有 Agent 模型上，将 kit 保留为可安装的能力套件。专家内容由配置中心选择版本，客户端负责校验、展示及安装为普通 Agent。此次不引入专家团或新的多 Agent 编排运行时。

### 1.2 目标

- 用户能从精选场景、分类、标签和搜索找到专家，召唤后直接编辑示例问题并发送。
- 新任务页可选择已安装专家或自建 Agent，并保留当前草稿。
- 专家、分类、场景、顺序和头像可独立发布，支持测试验证、生产发布及回滚。
- 保持 Agent 的本地持久化、用户编辑、技能关联和 OpenClaw 会话行为兼容。

## 2. 用户场景

### 场景 1：首次使用办公专家

**Given** 用户尚未安装目标专家，专家目录可正常加载。

**When** 用户在专家广场选择专家并点击“召唤”。

**Then** 主进程创建对应的普通 Agent，完成 OpenClaw 配置同步后进入该 Agent 的新任务页。示例问题进入输入框，只有用户发送后才发起模型请求。

### 场景 2：带着已有输入切换专家

**Given** 用户在新任务页填写了内容或添加了附件。

**When** 用户从“召唤专家”入口选择已安装专家或可用的自建 Agent。

**Then** 进入该 Agent 的新任务页，保留当前输入和附件；“召唤更多专家”打开专家广场。

### 场景 3：运营调整推荐内容

**Given** 维护者准备了新版本的专家内容，并通过协议和内容检查。

**When** 在 Overmind 发布该版本的清单。

**Then** 对应环境的客户端在下次符合刷新条件的访问中获取新目录，按下发顺序展示；已安装 Agent 的内容和用户修改保持不变。

### 场景 4：配置暂时不可用

**Given** 用户曾成功加载过当前环境的目录。

**When** 网络、配置、版本或摘要校验失败。

**Then** 使用本环境上次有效目录。没有有效缓存时展示重试入口，不静默使用另一个环境的配置。

## 3. 功能需求

### FR-1：入口与概念分离

侧栏原“专家套件”入口改为“专家广场”，使用独立的拟人专家图标。kit 更名为“套件”，移至“套件·技能·连接器”页面的首个 tab，保留原套件页面与安装能力。

### FR-2：专家发现

广场由精选场景与全部专家组成。支持名称、描述和标签搜索，分类及标签筛选；详情展示工作范围和示例问题。名称、说明、标签、示例及系统提示词均支持中英文。

精选场景使用横向卡片轨道、左右翻页按钮及滚动吸附。隐藏原生滚动条，保留触控板、触摸和键盘滚动，轨道可聚焦，边界按钮禁用。头像区域保持固定尺寸，无图时使用默认图标。

### FR-3：低门槛召唤与 Agent 兼容

召唤仅传递专家 ID，由主进程读取可信目录并安装或复用 Agent。已安装实例保留名称、提示词、技能和头像等快照；远程内容变更不覆盖用户修改。复用被停用的预设时重新启用，并防止并发重复安装。

新任务页入口列出可用的已安装预设和自建 Agent，切换时保留输入内容。示例问题始终是未发送草稿，不因选择专家自动执行任务。

### FR-4：内容发布与排序

分类、精选场景和全部专家的数组顺序即展示顺序，客户端不再保存一份本地专家名单。内容维护者可依据经脱敏汇总的任务需求调整顺序，保留校园、求职、投资、法务等场景的发现入口；不使用原始请求作为公开示例或提示词。

新增专家必须有独立的工作方法、明确交付物及可实际调用的能力。`skillIds` 只能引用目标客户端已有技能，不通过目录自动安装技能、插件或授予权限。专家数量和排序属于内容版本，不是客户端协议常量。

### FR-5：可验证的远程配置

采用“内容源 Git 仓库 → 不可变 CDN 目录 → Overmind 清单 → 客户端”的发布链路。测试与生产分别发布同一个 key，支持按清单回滚。校验失败不能替换上次有效内容。

## 4. 实现方案

### 4.1 内容源与数据协议

原始配置维护在独立的私有 `lobsterai-expert-store` 仓库：

| 文件 | 作用 |
|------|------|
| `catalog.json` | 版本、分类、精选场景和 `expertOrder` |
| `experts/<id>.json` | 专家名称、简介、身份、标签、技能、头像和示例问题 |
| `prompts/<id>.zh.md` / `.en.md` | 可独立审阅的中英文工作方法 |
| `dist/experts-<version>.json` | 确定性构建的完整目录，已发布版本不覆盖 |
| `releases/<version>.manifest.json` | Overmind 发布清单 |

Overmind 的 `expert-store` 值支持 JSON 对象或 JSON 字符串，协议如下：

```json
{
  "schemaVersion": 1,
  "version": "<content-version>",
  "catalogUrl": "<supported-https-cdn-url>",
  "sha256": "<sha256-of-raw-utf8-catalog-bytes>"
}
```

完整目录包含同一 `schemaVersion`、`version`，以及 `categories`、`scenarios`、`experts`。构建过程按 `expertOrder` 合并元数据和提示词；ID 必须唯一且稳定，场景引用必须存在，不能用同一 ID 替换为不相干的专家。

客户端以 `src/shared/agent/presets.ts` 和 `expertCatalogValidation.ts` 为协议依据。schema v1 限制最多 100 个分类、100 个场景、1,000 位专家，每位最多 20 个标签、12 个示例及 50 个技能。色调来自客户端有限枚举，不执行远程 HTML、CSS 或 JavaScript。

### 4.2 拉取、校验与缓存

`getExpertStoreUrl()` 与 skill-store、kit-store 使用相同的 `app.testMode` 选择规则。主进程 `ExpertStore` 完成以下步骤：

1. 合并同一端点的并发请求，读取对应环境缓存。
2. 拉取 Overmind 清单，限制 32 KiB；每次请求超时 10 秒。
3. 仅从允许的 HTTPS CDN 来源下载目录，不跟随重定向；完整目录不超过 4 MiB。
4. 校验原始 UTF-8 字节的 SHA-256、完整 schema、引用关系及版本一致性。
5. 将有效内容写入临时文件后原子替换缓存，再交付渲染进程。

缓存位于 `userData/expert-store/<endpoint-sha256>.json`，按完整配置端点隔离环境。成功后 5 分钟内复用目录，之后在请求时检查更新，无后台轮询。已有目录刷新失败时保留缓存，30 秒后允许下次请求重试。首次无缓存且失败时返回错误，由页面提供重试。

主动发布空目录合法。回滚允许使用较低版本号，内容由摘要识别。修改协议字段或新增视觉色调需要客户端适配，普通内容增删及排序无需客户端发版。

### 4.3 IPC、安装与 OpenClaw

渲染进程通过 `AgentIpcChannel.ExpertCatalog` 获取目录，复用原有 Agent 服务完成召唤。`agents:presets` 与 `agents:presetTemplates` 保持数组返回契约，供既有调用方兼容使用。

主进程依据专家 ID 选择校验后的模板，按当前语言创建普通预设 Agent，再等待 OpenClaw 配置同步完成后返回。不会增加新的数据库结构、运行时或 OpenClaw 补丁。

已安装实例可在断网或远程专家下架后继续从 Agent 入口使用。新目录影响新安装，不自动改写已有实例；并发安装会再次检查实例是否存在，自建 Agent 的 ID 冲突按既有分配策略处理。

### 4.4 头像与资源大小

支持已有 SVG 图标令牌与受支持 CDN 的 PNG、JPEG、WebP 地址，拒绝不受支持的协议、来源及异常 URL。推荐 256×256 WebP、单张低于 20 KB，原图只保留在内容源仓库，不下发。现有三个示例头像每张低于 5 KB，其余可以留空。

头像使用延迟加载、异步解码和无 referrer 请求，加载失败回退默认图标。配置中的头像不能注入可执行内容。

### 4.5 发布与回滚

1. 修改独立内容仓库，递增版本；检查中英文内容、能力绑定、示例问题和引用。
2. 运行构建及单元测试，提交可审阅的源文件与不可变目录。
3. 上传压缩资源和目录到 CDN，下载校验原始字节摘要，生成清单。
4. 先发布 test 的 `expert-store`，验证目录解析、展示顺序、头像和召唤。
5. 验证通过后，按发布授权将同一清单发布到 prod；只操作目标 key，不同步项目全部配置。
6. 读取两个环境的配置并校验版本、CDN 摘要及目录数量，记录发布结果。需要回滚时重新发布该环境以前的清单，不覆盖 CDN 文件或删除用户 Agent。

## 5. 边界情况

| 场景 | 处理方式 |
|------|---------|
| 清单超限、超时或非成功响应 | 拒绝更新，尝试本环境上次有效缓存 |
| 摘要或版本不一致、重复 ID、悬空场景引用 | 整份目录不生效，避免展示部分不一致内容 |
| test 切换到 prod | 使用不同端点及缓存，不互相回退 |
| 首次断网 | 展示失败与重试入口，不内置第二份专家目录 |
| 专家下架或远程提示词变化 | 已安装 Agent 继续保留本地快照与用户修改 |
| 专家依赖技能未安装或能力未配置 | 不隐式安装或授权，内容说明应与实际可用能力相符 |
| 头像为空或下载失败 | 固定尺寸的默认图标占位 |
| 重复召唤或并发安装 | 复用实例并防止重复创建 |
| 用户只选择专家，没有发送 | 不调用模型，不自动执行示例任务 |
| 精选场景超出屏幕宽度 | 无原生滚动条，保留翻页按钮和原生横向滚动能力 |

## 7. 验收标准

- 导航中的专家与套件明确分开，套件内容及原有 Agent 功能可继续使用。
- test、prod 分别从正确端点加载，列表、精选场景和筛选顺序与下发目录一致。
- 首次召唤可创建 Agent 并完成 OpenClaw 配置同步；重复召唤复用实例，示例保持为未发送草稿。
- 已有专家选择保留输入和附件，更多专家入口进入广场。
- 缓存隔离、损坏缓存、失败回退、版本回滚、无缓存错误、并发安装、头像校验等逻辑有单元测试覆盖。
- 变更的 TypeScript 文件通过仓库规定的 ESLint；主进程及 IPC 改动通过对应编译与单元测试。
- 在独立的本地验证环境检查中英文、浅深主题、窄屏、横向浏览及真实配置。自动化验证可通过浏览器或 Electron 调试接口完成，不占用用户键鼠。
- 本次临时端到端脚本、验证截图及浏览器 profile 不提交到应用仓库；有价值的单元测试保留。
