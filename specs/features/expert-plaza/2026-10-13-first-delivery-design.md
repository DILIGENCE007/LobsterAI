# 专家首问直接体验设计文档

## 1. 概述

### 1.1 问题与依据

原有热门专家首问常包含“我会提供材料”“先给我分析框架”等表述。新用户召唤后直接发送，得到的可能是资料请求、澄清问题或方案，无法体验实际交付能力。真实 Electron 验收中，旧 PPT 首问触发了受众、页数、模板三组问题。

此前 2026-10-06 至 10-12 的线上匿名聚合研究显示，办公、内容、技术、数据、学习、电商是主要可识别需求。样本存在分类重叠和大量未分类项，不能将分类计数直接换算成全体用户覆盖率。本轮优先改善当前排序前 24 位专家，不扩展专家数量。

### 1.2 目标

默认首问自带明确任务、完整素材、合理默认值和成品标准。用户召唤并原样发送后，无需中途补充主题、风格或资料，就能获得实际可打开的成果。第二、第三问保留真实业务任务模板。

## 2. 用户场景

### 场景 1：第一次制作 PPT

**Given** 用户没有准备任何附件，也不熟悉 Agent。
**When** 召唤 PowerPoint 专家并原样发送默认问题。
**Then** 专家使用问题内的模拟咖啡店经营数据制作六页可编辑 PPTX，检查文件并给出可打开的链接；不再询问受众、模板和页数。

### 场景 2：已有旧模板或用户改过的 Agent

**Given** 本地已经有同一 presetId 的 Agent，其指令、模型、名称或技能可能被用户修改。
**When** 从新版专家目录再次召唤。
**Then** 复用本地实例，用新版首问创建新会话草稿；不覆盖 Agent 的个性化配置和历史会话。已有指令可能改变执行行为，因此兼容性验收也使用旧实例实际执行。

### 场景 3：执行真实业务任务

**Given** 用户改写问题，要求处理真实文件、发布或操作业务账户。
**When** 关键材料或授权不足。
**Then** 仍可询问必要信息；演示任务“不追问”的约定不授权虚构业务数据或越过操作权限。

## 3. 功能需求

- 首问具体到任务对象、素材或数据、输出格式与必要限制，避免依赖未提供的附件、账号和外部素材。
- 模拟数据应在成果中标注。文件整理只处理新建示例目录；网页演示只读取公开信息；媒体演示不要求用户上传素材。
- 要求成品时，不能仅给大纲、代码片段、计划或口头承诺；文件须存在、可读，并检查关键指标和展示效果。
- 新安装的应用开发、数据分析、流程自动化专家不再默认选择只读的 `create-plan` 技能。
- 保留所有稳定专家 ID、分类、场景、头像和第二/第三问；不迁移或重写旧 Agent 的 systemPrompt、identity、model、skillIds、workingDirectory。

## 4. 实现方案

### 4.1 目录配置

在独立内容仓库 `lobsterai-expert-store` 修改前 24 位专家的双语 `starterPrompts[0]`。构建脚本为新安装专家的 systemPrompt 拼接双语通用交付原则：利用完整上下文直接执行，非关键细节采用合理默认值，验证实际文件，按当前任务选择技能，明确工具限制。客户端 schema 保持 v1。

数据分析另增加统计口径约束：不同月份不等于同一人群，不能将净增订单/净增访客当作新增人群真实转化率；总量数据只支持提出待验证归因。

### 4.2 兼容边界

`AgentManager.addPresetAgent()` 继续先找本地 preset 实例，存在即复用。目录刷新只更新此前已定义为受管理的默认头像，不改变业务配置。新版示例由专家广场传入新会话草稿，不写进已有 Agent 的指令文件。

单元测试覆盖目录升级后的两条路径：旧实例仍保留原配置；新安装接收新版指令和技能。真实验收保留旧 PPT、应用开发和图片专家实例，并比较测试前后的业务字段。

### 4.3 本地验收与材料

通过 Electron 调试接口操作真实召唤按钮、输入框和 Enter，使用已登录账户的套餐模型。独立本地验收资料目录保存会话、成品、结构检查结果和截图；不使用 OS 键鼠控制，不将临时端到端驱动脚本提交到仓库。

本轮目录内容通过仅对验收进程生效的本地传输替换下发，仍经过正常目录校验、Agent 安装与 OpenClaw 执行。发布到 CDN、Overmind 和远程 Git 留待用户验收后另行执行。

## 5. 边界情况

| 场景 | 处理 |
|------|------|
| 用户已经改过专家 | 保留配置；不为通过首问测试重装或强制更新 |
| 多次召唤同一专家 | 复用 Agent，创建独立草稿/会话 |
| 图像服务不可用 | 首问允许交付明确说明制作方式的 SVG/PNG 替代物，不冒充模型生成 |
| 在线来源不可访问 | 标注未取得，保留可验证来源，不编造检索结果 |
| 工具验证失败或超时 | 尝试有依据的恢复，明确未验证部分，不无限等待或虚报成功 |
| 统计归因缺少分组数据 | 提出假设与验证实验，不将总量变化解释成人群因果 |

## 6. 涉及文件

- 内容仓库：`experts/*.json`、`prompts/first-delivery.*.md`、数据分析指令、构建脚本与目录单元测试。
- 客户端：`src/main/agentManager.test.ts` 增加目录升级兼容回归；头像迭代见同目录的分类头像设计文档。
- Windows 表格重算的验收阻塞修复见 `specs/bugfixes/xlsx-recalculation/2026-10-13-windows-recalculation-design.md`。

## 7. 验收标准

- 原样发送首问，真实模型会话完成且没有中途用户补充或澄清工具请求。
- PPT/Word/Excel 可读取且结构、关键数据正确；网页能打开且核心交互可用；图像、视频为实际可展示文件。
- 覆盖办公、文件整理、内容、媒体、开发、数据与电商等主要需求，分别记录成功、失败和复测，不用静态配置检查冒充模型验收。
- 保留可演示截图和原始产物；旧 Agent 业务配置保持一致。
- 本地提交后合入体验分支，启动合并版本；本轮不推送或更新远程 PR/配置。
