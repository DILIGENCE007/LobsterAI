# 开发环境登录回跳多开实例修复设计

## 1. 概述

### 1.1 问题

使用 `LOBSTERAI_DEV_USER_DATA_DIR` 指定独立数据目录启动 Electron 后，浏览器通过 `lobsterai://` 回跳时可能启动第二个窗口，原窗口没有收到登录结果。

### 1.2 根因

未打包应用注册协议时只保存 Electron 可执行文件和应用入口。Windows 启动协议进程时不继承原启动终端中的环境变量，导致新进程使用默认 `userData`，与原测试实例使用不同的单实例锁。`NODE_ENV`、`ELECTRON_START_URL` 也会丢失，冷启动时可能加载另一个渲染资源版本。

## 2. 用户场景

**Given** 用户通过独立数据目录运行开发版，并从该窗口发起浏览器登录。

**When** 浏览器使用已注册的 `lobsterai://` 协议打开回调。

**Then** 新进程在获取单实例锁前恢复相同目录，将回调交给原实例后退出。如果原实例已关闭，则恢复对应开发页面。

## 3. 功能需求

- 开发协议参数保留实际使用的绝对数据目录，而不是依赖父进程环境变量。
- 使用本地开发服务器时，同时保留其地址，使冷启动继续加载相同渲染页面。
- 参数只在未打包应用中生效；安装版忽略这些开发参数，保持原有协议注册行为。
- 不改变授权码处理、账号存储和本地 HTTP 登录回调流程。

## 4. 实现方案

`developmentProtocolContext.ts` 集中定义开发协议参数、解析和构造逻辑。`main.ts` 在配置 `userData` 前解析上下文；协议注册使用同一组规则构造参数。

| 参数 | 行为 |
|------|------|
| `--lobsterai-dev-user-data-dir` | 绝对路径优先于开发环境变量；相对路径不生效 |
| `--lobsterai-dev-start-url` | 只接受无凭据、无查询或片段、根路径的本地 HTTP(S) 地址；有效时恢复开发渲染模式 |

本地地址限 `localhost`、`127.0.0.1` 和 IPv6 loopback。未指定参数时继续使用现有环境变量和默认值。使用生产渲染 bundle 的未打包应用只记录数据目录，不因协议回跳切换成 Vite 页面。参数以独立 argv 项传给 Electron，不拼接 shell 命令。

## 5. 边界情况

| 场景 | 处理 |
|------|------|
| 系统拉起进程没有原终端环境变量 | 从注册的参数恢复目录及本地开发页面 |
| 外部终端继承了另一份开发目录 | 明确注册的绝对目录优先 |
| 路径包含空格 | 保持为单个 argv 参数，由 Electron 注册协议命令 |
| 远程、带凭据或非 HTTP(S) 渲染地址 | 不从协议参数启用，不写入注册参数 |
| 已打包应用收到开发参数 | 忽略，使用原有安装版路径规则 |

## 6. 验收标准

- 单元测试覆盖环境丢失后的上下文往返、目录优先级、相对路径、安装版隔离、生产 bundle 和地址边界。
- 修改文件通过 ESLint，主进程通过 TypeScript 编译，原登录回调测试通过。
- 独立数据目录启动后，Windows 注册的命令包含该目录及本地开发地址。
- 使用不含授权码的协议探针验证：原实例收到 `second-instance` 激活，新进程退出，默认数据目录没有启动第二个主进程。验证不消耗登录授权码、不改变登录状态，临时验证脚本不提交。
