# 专家召唤后侧栏会话隐藏修复设计

## 1. 概述

### 1.1 问题

从专家广场召唤专家后，侧栏对应 Agent 可能仍然收起。发送首条消息进入会话后，该分组没有自动展开，用户难以确认新会话的位置。

### 1.2 根因

侧栏独立持有并保存分组展开状态，仅在首次加载且没有已展开分组时设置默认值。专家召唤只切换 Agent、准备草稿；创建会话也没有触发分组展开。

## 2. 用户场景

**Given** 专家的侧栏分组处于收起状态。

**When** 用户从专家广场召唤专家，或在输入框选择已有专家。

**Then** 对应分组展开，草稿保持原入口的行为。用户发送后，进入的新会话所在分组也会展开。

## 3. 功能需求

- 新安装、已安装、重复召唤同一专家都能展开对应分组。
- 会话导航及新会话创建自动展开会话所属 Agent，不依赖当前输入框的 Agent 选择。
- 保留其他分组的展开状态。用户手动收起后，消息流、任务标题、运行状态及 Agent 信息刷新不得强制重新展开。
- 保持专家广场的全新草稿及已有专家选择时保留输入、附件的原有行为。

## 4. 实现方案

- `expertOnboarding.ts` 在两种专家入口切换 Agent 后，通过 `agentSlice` 写入一次性的侧栏展开请求。
- `useAgentSidebarState.ts` 在侧栏偏好加载完成、目标 Agent 可用后展开并消费请求，避免异步偏好覆盖刚发生的召唤。
- 同一 Hook 监听当前会话 ID 及所属 Agent ID，导航变化时展开对应分组；不订阅完整会话对象作为展开触发条件。
- 展开请求仅保存在当前渲染进程的 Redux 状态；最终展开状态沿用原侧栏偏好持久化。

## 5. 边界情况

| 场景 | 处理方式 |
|------|---------|
| 同一专家再次召唤 | 上次请求已消费，可以再次触发展开 |
| 侧栏偏好或 Agent 列表尚未加载 | 保留请求，待依赖就绪后处理 |
| 删除待展开的 Agent | 清除该请求 |
| 手动收起正在输出的会话分组 | 流式更新不改变手动收起状态 |
| 其他 Agent 后台任务更新 | 不自动展开其分组 |

## 6. 验收标准

- 单元测试覆盖专家两种入口、重复召唤、无效专家及草稿保留。
- 在独立 Electron 渲染环境验证偏好延迟、首条消息、重复召唤、手动收起及后台任务更新，不占用用户键鼠。
- 变更文件通过 ESLint；保留临时验证脚本在仓库外，不提交端到端脚本。
